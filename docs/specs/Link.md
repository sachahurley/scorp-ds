## Intent

<!-- HUMAN-SECTION:intent -- This section is preserved across auto-updates -->

LINK COMPONENT

Inline text link for navigation. Always renders a real anchor (or a custom
router link via `as`/`asProps`, the same polymorphism as ListRow), never a
button: links navigate, Button acts. Plate-shaped link CTAs stay on `Button`
with `href`; Link owns prose, captions, and nav lists.

It is the first consumer of the `text.link` / `text.link-hover` semantic
tokens, which existed before this component but were orphaned.

VARIANTS:
- inline (default): persistent underline, the safe treatment inside body text
  (color is never the sole indicator of a link)
- quiet: underline only on hover/focus, for nav lists and footers where
  position already signals the link

There is deliberately no disabled state: a link without a destination is just
text, so render text.

## Do / Don't

<!-- HUMAN-SECTION:do-dont -- This section is preserved across auto-updates -->

- DO use Link for navigation inside prose and for nav/footer lists.
- DO use `as`/`asProps` for router links instead of wrapping.
- DON'T use Link for actions (open modal, submit); that's Button.
- DON'T use `Button variant="link"` for inline text links; it is the legacy
  path and Link supersedes it for text-in-prose. Plate-shaped link CTAs stay
  `Button href`.
- DON'T disable a link; drop the wrapper and render text.

<!-- /HUMAN-SECTION:do-dont -->

## Composition Rules

<!-- HUMAN-SECTION:composition -- This section is preserved across auto-updates -->

Inherits font size from context (no size axis), so it sits correctly in any
text tier. Inside `ListRow`/`Table` cells prefer the row's own interactive
modes before nesting links.
